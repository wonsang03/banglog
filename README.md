## 서비스 흐름

1. **입주 첫날, 방 전체를 한 바퀴 찍어요.** 어디를 어떻게 찍을지 몰라도 됩니다. 방 가운데 서서 제자리에서 360° 돌면, 그 화면으로 방 구조를 파악해 도면을 만듭니다.
2. **찍기 좋은 자리에 핀을 꽂아 드려요.** 방 전체가 빠짐없이 담기는 자리 10곳을 고릅니다. 방 전체를 덮는 6곳과, 놓치기 쉬운 4곳(문 뒤·콘센트·천장 모서리·장 안)입니다. 핀은 서는 자리, 부채꼴은 카메라를 향할 방향입니다.
3. **핀마다 기준 사진을 한 장씩 남겨요.** 찍는 순간 촬영 일시와 보관 번호가 붙습니다. 흠이 보이면 가까이 한 장을 덧붙일 수 있습니다(선택).
4. **1년 뒤, 계약 연장, 퇴실 때 같은 핀에서 똑같이 찍어요.** 카메라에 입주 때 사진이 겹쳐 보여 같은 구도로 맞출 수 있습니다. 기록 화면에서 두 사진을 밀어 보면 무엇이 달라졌는지 바로 보입니다.

## 실행 방법

빌드 없이 정적 파일만으로 동작합니다.

1. `index.html`을 브라우저(Chrome·Edge·Safari)에서 엽니다. 컴퓨터에서는 왼쪽에 프로젝트 소개, 오른쪽에 휴대폰 화면이 나옵니다. 휴대폰에서 열면 앱만 꽉 차게 보입니다.
2. 로컬 서버로 열려면 이 폴더에서 `python -m http.server 8000`을 실행하고 `http://localhost:8000`에 접속합니다.
3. GitHub Pages·Netlify·Vercel에 폴더째 올리면 그대로 동작합니다. 휴대폰에서 https 주소로 열면 실제 카메라로 찍을 수 있습니다.

**3분 체험 순서** (컴퓨터 화면 왼쪽 바로가기)
- **사용법 보기**: 온보딩 4단계
- **입주 촬영 처음부터**: 방 전체 찍기(찍기 시작을 누르면 9초 동안 360° 회전) → 핀 10곳 확정 → 핀마다 셔터 → 사용하기 → 보관 도장 → 다음 핀
- **1년 뒤 퇴실 상황**: 기록에서 2번 핀(창문 쪽 벽)의 입주·퇴실 사진을 밀어 비교. 방충망 찢어짐이 새로 생긴 것을 확인할 수 있습니다. 6번 핀(바닥)과 4번 핀(주방)도 달라져 있습니다.
- **확인서 미리보기**: PDF 저장

## 프로젝트 목적과 문제

원룸·빌라에 입주하는 20~30대 세입자는 보증금 분쟁에 대비해 입주 사진을 찍지만, 세 가지 문제가 있습니다.
1. 어디를 찍을지 기준이 없어 **촬영을 놓칩니다**.
2. 사진이 갤러리에 섞여 퇴실 때 **찾기 어렵고, 촬영 시점을 믿게 하기 어렵습니다**.
3. 입주와 퇴실 사이에 **다시 기록할 계기가 없습니다**.

근거: 03 제안서 5W1H. 05 모의 공간 리허설에서는 하자 10곳 중 5곳 누락, 사진 찾기 1분 50초, 신뢰도 3점이 측정되었고, 이 값은 가상 자료입니다.

## 디자인 · 구현 포인트

- **방향**: 차분한 흑백 화면에 주황 포인트 한 가지(핀, 진행, 안내), 보관 완료는 초록 도장. 글꼴은 Pretendard이고, 한국어는 단어 단위로 줄을 바꿉니다.
- **도면**: 벽, 문 호, 창, 가구를 건축 도면처럼 그린 SVG입니다. 선택한 핀은 이름표와 시야 부채꼴, 전체 핀은 시야 범위로 보여 줍니다.
- **3D 방 렌더러(`js/room3d.js`)**: 도면 좌표로 방(벽, 장판, 창문, 책상, 붙박이장, 주방, 침대)을 3D로 세웁니다. 핀마다 정해진 위치·방향·높이의 카메라로 모의 사진을 그립니다. 같은 핀이면 언제 찍어도 구도가 정확히 같고, 그 사이 생기거나 커진 흠(방충망 찢어짐, 바닥 찍힘, 상판 열 자국, 곰팡이 등)만 달라집니다.
- **사진 품질**: 창문에서 들어오는 빛이 벽·천장·바닥에 번지고, 창틀 두 칸 모양 햇빛이 바닥에 떨어집니다. 가구 면에는 위아래 명암과 모서리 하이라이트를 넣고, 벽걸이 에어컨 같은 원룸 디테일을 더했습니다. 1.5배 해상도로 그리고 약한 대비와 따뜻한 톤으로 보정합니다.
- **방 전체 찍기(360°)**: “찍기 시작”을 누르면 방 가운데에서 본 화면이 창문 → 주방 → 침대 → 현관 → 붙박이장 → 책상 → 창문 순서로 한 바퀴 돕니다.
  - 화면 가운데 세로선이 지금 담는 위치입니다. 선을 지나간 쪽은 밝아지고 방 모서리·가구 윤곽선이 붙으며, 아직 담지 않은 쪽은 살짝 어둡습니다.
  - 아래 안내판에는 돈 각도(0~360°), 지금 담는 곳, 위에서 본 레이더(보는 방향과 지금까지 담은 범위), 이어 붙는 파노라마 띠가 함께 나옵니다.
  - 구현: 15°마다 한 장씩 그린 화면을 원통 파노라마로 이어 붙여 두고, 매 프레임은 그 파노라마를 원근 화면으로 다시 펼치기만 합니다. 방을 매번 새로 그리지 않아서 부드럽게 돕니다.
- **홈**: 가장 최근에 찍은 ‘방 전체’ 사진을 큰 카드로 보여 주고, 계약 기간 타임라인(입주 → 정기 점검 → 퇴실 → 계약 만료, 오늘 위치)과 핀별 최근 사진 줄을 둡니다.
- **기록**: 위에서부터 도면 → 사진 → 사진 줄 순서입니다. 맨 위 “도면에서 위치 보기”에서 핀이 방의 어디에 있는지 보고 누르면, 그 아래에 같은 구도로 찍은 사진이 비교 슬라이더로 나옵니다. 그 아래 핀별 사진 줄을 가로로 넘기며 다른 핀으로 옮겨 갈 수 있습니다. 도면과 사진 줄은 선택을 공유해서, 어느 쪽에서 고르든 다른 쪽도 같은 핀으로 바뀌고 사진 줄은 고른 핀을 가운데로 옮깁니다. 비교할 시점은 칩으로 바꾸고, 가까이 찍은 사진은 따로 모아 보여 줍니다.
- **카메라**: 오른쪽 위 미니 도면에 지금 핀의 위치와 방향을 표시합니다. 휴대폰에서는 기울기를 보여 주는 수평계가 나오고, 수평이 맞으면 초록색으로 바뀝니다.
- **체감 속도**: 쉬는 시간에 모의 사진을 미리 그려 두고, 사진이 많은 목록은 자리 표시(반짝임)를 먼저 보여 준 뒤 한 장씩 채워 화면이 멈추지 않게 했습니다.
- **기기 프레임**: 컴퓨터에서는 iPhone 크기 프레임(다이내믹 아일랜드, 상태 표시줄)에 넣어 실제 앱처럼 보여 줍니다.

## 접근성 · 개인정보 · 표현

- 핀은 번호, 실선과 점선, 체크 배지로 함께 구분해 색에만 의존하지 않습니다.
- 키보드로 도면 핀을 고를 수 있습니다(Tab, Enter). 온보딩은 좌우 화살표로 넘깁니다. 다크 모드에 대응합니다.
- 기기에서 ‘움직임 줄이기’(`prefers-reduced-motion`)를 켜면 장식용 애니메이션(도면 그려지기, 도장, 화면 전환 등)을 끕니다. Windows에서 “애니메이션 효과”를 끄거나 원격 데스크톱으로 접속하면 이 상태가 됩니다. 방 전체 찍기의 회전 화면은 실제 앱의 카메라 화면을 대신하는 내용이라 그대로 보여 주고, 손떨림 같은 꾸밈만 뺍니다.
- 사진은 이 브라우저의 `localStorage`에만 저장되고 서버로 보내지 않습니다.
- “법적 효력 보장”이라는 표현은 쓰지 않습니다. 화면에는 “시점과 원본이 추정되는 기록”으로만 표현했습니다.

## 한계(가정·모의 부분)

- 방 구조 파악과 핀 위치 계산은 모의입니다. 도면과 핀 10곳은 미리 정한 값이고, 360° 도는 화면도 실제 카메라가 아니라 3D 렌더러가 그린 모의 화면입니다.
- 실제 카메라가 없으면 3D 렌더러가 그린 모의 사진을 씁니다.
- 보관 번호는 무작위 예시 값이며 실제 공인전자문서센터와 연동되지 않습니다.
- 흠 판별은 사용자가 직접 합니다(AI 판별은 제외 범위).
- 05 연구 자료가 가상 리허설이므로 수치는 실측 후 바꿔야 합니다.
